用代码堆出来的无人机

2026.11.02 约 8 分钟 标签：Three.js / 几何 / 交互

拆解实验室里那台无人机，没有 .glb、没有 .obj、也没有贴图文件。 它由大约三千行 JavaScript 现场拼出来：每个零件都是几何体，每个动画都是插值。 这篇写一下它大概是怎么搭的。

为什么不用现成模型

最直接的理由是没有模型文件。手头没有官方的三维资产，也不想去扒别人的。 另一个理由是：程序化生成的模型天生带参数——想改机臂长度、桨叶半径，改一个数字就行， 还能让零件各自独立运动，做「拆开/装回去」这种交互非常顺手。

零件清单就是数据

整台机器被切成九个模块，每个模块是一个对象：编号、中文名、英文名、分类、一句话规格、 拆解方向、以及详情面板里的那张参数表。 

{
  id: "battery",
  num: "03",
  name: "智能飞行电池",
  en: "INTELLIGENT FLIGHT BATTERY",
  category: "能源系统",
  labelSpec: "4276 mAh · 45 min",
  explode: { x: 0, y: 1.58, z: -0.13 },   // 拆解时往哪飘
  specs: [
    ["电池容量", "4276 mAh"],
    ["电池能量", "64.96 Wh"],
    ["最长飞行时间", "45 分钟"]
  ]
}

UI 全部由这份数据驱动：左侧清单、场景里的引线标签、右侧详情表、拆解百分比， 都是同一个数组渲染出来的。加一个零件，只要在这里加一段，再补上对应的几何体。

机身与机臂：从盒子开始

机身主体是几个 BoxGeometry 叠出来的：上盖、下壳、电池仓、云台接口。 为了不像一块砖，边角用 RoundedBox 的思路处理，再靠材质和光照把轮廓拉出来。

机臂是细长的盒子，前端接电机座，内部走线用一条略暗的细圆柱暗示。 前后机臂分成两组，方便单独做折叠动画。

云台：两种镜头，一个壳

双摄云台是整个模型里零件最多的部分：一个横滚臂、一个俯仰臂、一个镜头壳、两个镜头圈、 两片镜片。镜片用 CylinderGeometry 压扁，材质给一点金属度和高粗糙度反射， 在画面里就会有一小圈亮边——那种「玻璃感」其实全靠这点反射。

螺旋桨：三叶，靠旋转复制

一片桨叶是拉伸出来的曲面，绕轴复制三次、每次转 120°，就是三叶桨。 四个桨座各挂一组，对角同向、相邻反向——这是四旋翼抵消反扭矩的方式，模型里也照这个来。 

// 一片桨叶，复制三份，每份转 120°
for (let i = 0; i < 3; i++) {
  const blade = makeBlade();
  blade.rotation.y = (Math.PI * 2 / 3) * i;
  hub.add(blade);
}

拆解动画：一个数字控制全部

每个可拆零件都有自己的 progress（0 到 1）。点击某个零件时，目标值变成 1， 每帧朝目标插值一点点，位置就等于基准位置加上 explode 向量乘以 progress。 全部拆开就是把所有可拆零件的目标都设成 1。 

part.position.copy(part.base).addScaledVector(part.explode, part.progress);

这样切换状态永远是平滑的，不会跳帧；也顺便得到了「结构分离度」那个百分比—— 把所有 progress 平均一下就是。

连线和标签

场景里那些引线和文字标签不是三维物体，而是一层 SVG 覆盖在画布上。 每帧把三维坐标投影成屏幕坐标，再更新 SVG 线段和 div 的位置。 好处是文字永远清晰、不会随相机拉伸变形，样式也能直接用 CSS 写。

可以直接分享某个状态

页面读了两个 URL 参数：?part=battery 进来就选中并拆开电池， ?exploded=1 进来就是全部拆开的状态。两个可以叠加： 

https://llla.ningfu334.workers.dev/lab/?part=battery&exploded=1

本来是为了截图方便，后来发现分享单张「某个零件」的链接挺好用，就留着了。

性能上做的几件事

  • 几何体全部在初始化时建好，动画里只改 position / rotation，不重建。
  • 光照只用两盏方向光加环境光，没有开阴影贴图——阴影靠一个软圆片假装。
  • 像素比压在 2 以内，移动端再降一档。
  • 页面不可见时停掉渲染循环，回来再启动。

还没做的

  • 真实材质的贴图（现在全是纯色 + 金属度）。
  • 把拆解过程导出成视频，方便发到别的地方。
  • 移动端单手拖拽的手感还能再调。
